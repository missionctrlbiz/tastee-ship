tasteeship github ↗

Agents ship. Taste decides.

tship is a local CLI harness that runs the “make it better” loop against your own repo: your taste in a rules file, a verification gate the model never sees, a checkpoint per round, an out-of-band kill switch, and a live dashboard — zero runtime dependencies, Node ≥ 18.

why

The loop works. The stopping doesn't.

Tell a coding agent “make it better” on repeat and it over-builds — the reference run shipped a pumpkin-carving feature nobody asked for. tasteeship's origin story is that experiment turned into a product: halting on regression, over-build, or user rejection instead of forcing another change.

the gate

outputs_max — then it halts and reports

SHIP

Every round passes the verification layer: required selectors still present, JS refs resolve, taste strings absent, LOC budgets intact. Ships as a git checkpoint.

RETRY

A rejected proposal burns one of the round's outputs. The harness reports exactly which check tripped — the model never sees the verdict logic.

HALT

Over-build halts on taste/budget, regression on green→red checks, outputs-max on an exhausted budget. The repo rolls back; the report explains.

quickstart

Local-first, no dependencies

$ git clone https://github.com/missionctrlbiz/tastee-ship && cd tastee-ship
$ npm link
$ tship init                    # detect framework, scaffold config + rules.md
$ tship keys add anthropic     # your key → .env.local (0600, never committed)
$ tship run --rounds 50        # the loop (mock provider needs no key)
$ tship dashboard              # rounds, trends, scrubber, kill button
$ tship stop                   # halt + rollback, out-of-band

Providers

Anthropic, any OpenAI-compatible endpoint you own (GLM, DeepSeek, OpenRouter), or the deterministic mock for gate testing with zero keys.

Providers can't rush the gate

Proposals are validated in Node — selectors, JS→DOM references, taste strings, LOC/file budgets — before anything is committed. Checkpoints make every step idempotent.

Kill is out-of-band

tship stop (or the dashboard's red button) aborts in-flight calls, rolls the repo back to the last good checkpoint, and marks the run killed. Resuming verifies the checkpoint first.
